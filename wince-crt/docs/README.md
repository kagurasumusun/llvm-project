# LLVM/Clang Windows CE toolchain

The Windows CE support is integrated into the LLVM/Clang/LLD source trees
per LLVM design: driver support in clang/lib/Driver, target info in
clang/lib/Basic/Targets, image handling in lld/COFF, codegen hooks in
llvm, and this runtime project (`wince-crt`, an LLVM runtime).  The goal:

```
MSVC-compatible C/C++ source
        │  clang / clang-cl  --target=arm-pc-wince
        ▼
        LLVM IR  →  LLVM ARM backend (AAPCS, soft-float, ARMv4T baseline)
        ▼
        COFF objects (IMAGE_FILE_MACHINE_ARM, WinCE relocations)
        ▼
        LLD (lld-link) with Windows CE image defaults
        ▼
   WinCE EXE / DLL   →  Windows CE device (ARM)
```

without any Microsoft compiler, linker, CRT, or Platform Builder, and
without any runtime dependency on GCC or CeGCC.

## Design decisions (evidence-based)

All binary-format decisions were extracted from the CeGCC binutils fork
(`salman-javed-nz/binutils-gdb`, branch `ce-2.43.1`, the linker used by the
CeGCC 14.2 toolchain deployed on real devices), not guessed:

* **Machine type**: `IMAGE_FILE_MACHINE_ARM` (0x01c0).  bfd writes
  `ARMPEMAGIC` (0x1c0) for the `ARM_WINCE` targets (coffcode.h,
  `coff_write_object_contents`).
* **No underscore decoration**: `arm-wince-pe` sets `TARGET_UNDERSCORE=0`
  (bfd/pe-arm-wince.c) and the ld emulation uses `INITIAL_SYMBOL_CHAR=""`.
* **Image base**: EXE 0x00010000, DLL 0x10000000 (ld `arm_wince_pe.sh`
  overrides `NT_EXE_IMAGE_BASE`; DLL keeps `NT_DLL_IMAGE_BASE`).
* **Section/file alignment**: 0x1000 / 0x200 (same emulation file).
* **Subsystem**: `IMAGE_SUBSYSTEM_WINDOWS_CE_GUI` (9); entry default
  `WinMainCRTStartup` (ld pe.em default entry table, subsystem 9 row);
  console style maps to subsystem 2 + `mainCRTStartup`.
* **EXEs carry no base relocations** (the CE kernel maps EXEs at their
  fixed base; binutils only emits relocs for DLLs or with --dynamicbase).
  DLLs keep `.reloc` (the CE kernel relocates DLLs at load time).
* **Import thunks**: ARM-mode `ldr ip,[pc]; ldr pc,[ip]; .word IAT`
  identical to binutils `jmp_arm_bytes` (ld/pe-dll.c).
* **Thumb bit**: the WinCE loader uses bit 0 of addresses/entry RVA to
  switch code mode (ld `--thumb-entry` writes `val | 1`).  Producers mark
  Thumb functions with bit 0 set in the COFF symbol value (ELF
  convention); LLD preserves it.  Desktop-WinARM (ARMNT) images keep the
  "everything is Thumb" behavior.
* **CRT entry contract**: the CE loader invokes the entry with WinMain's
  argument set; CeGCC crt3.c dispatches to WinMain and a lib adapter
  dispatches WinMain→main.  Our port preserves that and additionally
  provides a real `mainCRTStartup` (argv built from `GetCommandLineW`).
* **atexit**: coredll exports no `atexit`/`exit`/`_cexit`; the CeGCC
  mingwrt provides a private table (atexit.c, Wine-derived `__dllonexit`).
  Our port vendors it unchanged and adds C++ finalization via libc++abi.

**ABI**: C ABI = the WinCE ARM ABI as used by VS2008/Platform Builder and
compatible with CeGCC binaries at the OS call boundary: AAPCS base
standard, soft-float (no VFP in the default configuration), MS bitfield
layout, aggregates >4 bytes returned in memory, `char *` va_list,
no symbol decoration.  C++ ABI = Generic ARM (Itanium) with Itanium name
mangling, because the C++ runtime is the open-source libc++/libc++abi;
MSVC's C++ ABI/SEH EH is not implementable without the MS CRT (documented
constraint — C-level interop with the OS and CeGCC-built C DLLs is
unaffected).

**EH plan** (C++ exceptions, not yet implemented): ARM EHABI
(`.ARM.exidx`/`.ARM.extab`) with LLVM libunwind and libc++abi
`__gxx_personality_v0`; no OS involvement is required.  Missing pieces:
an ARMCOFF MC streamer emitting the exidx/extab records, and LLD COFF
handling for `.ARM.exidx` (bounds symbols, sorting, relocation
application).

## Layout

* `lib/` — the new port layer only (crt0/dllcrt0/crtxcu/init_args/
  winmain/pthread).  Unchanged CeGCC mingw-runtime members are compiled
  directly from third-party/mingwrt by CMakeLists.txt.
* `CMakeLists.txt` — LLVM runtime project: import libraries (llvm-dlltool),
  CRT objects, mingwex supplement, header overlay, sysroot assembly.
* `test/` — end-to-end link/inspect scripts.
* `docs/` — build instructions, device testing procedure, design notes.
* `clang/test/Driver/wince.c`, `lld/test/COFF/wince-image.s` — in-tree
  lit tests for the driver and linker behavior.

## Third-party assets

The WinCE-side sources come from three git submodules (see
`docs/BUILDING.md` for the exact build flow):

* `third-party/mingwrt` (CeGCC mingw-runtime): the COREDLL definition
  files, the public-domain CRT glue sources (atexit, argv, adapters), the
  portable mingwex subset, and the C header overlay.  Consumed directly;
  no GCC required.
* `third-party/w32api` (CeGCC w32api): the WinCE platform headers and the
  `libce/*.def` system-DLL definitions from which the import libraries
  are generated with `llvm-dlltool -m armce`.
* `third-party/binutils-gdb` (CeGCC binutils fork, `ce-2.43.1`): the
  normative reference for the `arm-wince-pe` PE image format (headers,
  entry table, thunks, relocation behavior) this toolchain reproduces
  with LLD.  Not built, not installed, not needed at run time.

The compiler, linker, runtimes and sysroot assembly are LLVM/Clang/LLD
plus this project; nothing depends on CeGCC's GCC/binutils at build or
run time.
